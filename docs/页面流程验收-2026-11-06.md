# 页面流程验收与自动化

2026-11-06执行过独立数据库真实浏览器验收；2026-11-07首版将操作链转为Playwright Chromium测试，代码位于e2e目录，并接入Windows/Ubuntu CI。本地三个自动用例均通过。

## 覆盖场景

| 场景 | 检查内容 |
| --- | --- |
| 空列表与校验 | 初始指引、名称/URL必填、空格名称后端拒绝并保留输入 |
| 创建与编辑 | 自动HTTP200；名称/URL修改；重定向输入及最终地址；旧历史仍保留检查时地址 |
| 暂停/恢复 | 暂停时仍能手动检查，恢复后继续自动监测 |
| 异常与筛选 | 500、超时、搜索、无匹配提示、正常/异常/暂停筛选 |
| 历史 | 55条真实样本首批50、追加5、30点趋势；关闭重开恢复首批、切换目标不串记录 |
| 删除 | 取消保留、确认移除、历史接口404；数据库级联另有Go断言 |
| 连接 | 真实隔离服务停止后保留旧数据和提示；同库重启刷新恢复 |
| 窄屏 | 320/390宽页面不整体溢出；历史表格局部滚动，弹窗不越界 |

## 复现

自动化：安装Node24及锁定依赖，执行 `npx playwright install chromium`、`npm run test:e2e`。用例自动创建临时SQLite、动态回环端口和测试HTTP上游，结束清理进程。

手工体验：PowerShell7在项目目录运行 `.\scripts\page-acceptance.ps1 -Action Start`，按输出打开隔离页面；`-Action Seed` 通过真实API生成55条暂停样本，`-Action Stop` 核对PID、程序路径、启动时间后停止进程并保留日志。默认18082/18083可改端口。

`scripts/test-page-acceptance.ps1` 在18084/18085回归身份校验及饱和重试。Seed只对明确未接受的409限时重试，不对可能已接受请求的网络错误盲目重试；等待记录数与running=false，避免写入完成但槽位尚未释放的窗口。
