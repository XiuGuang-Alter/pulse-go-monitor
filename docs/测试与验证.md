# 测试与验证

| 层次 | 验证内容 |
| --- | --- |
| HTTP检查 | 状态、输入、重定向、超时、取消、连接失败、正文生命周期 |
| SQLite | 事务、持久化、版本保护、删除级联、游标、1000条/30天保留 |
| 调度 | 并发上限、去重、暂停、自动/手动、停止，在途编辑/暂停/删除 |
| API | 生命周期、输入/正文错误、Host/Origin、静态资源 |
| 演示 | 动态端口、冲突、重复启动、初始化失败释放资源 |
| 真实进程 | Windows私有控制台Ctrl+C、Unix SIGINT；取消、端口释放和持久化 |
| 前端时序 | 旧响应迟到、保存后刷新失败不回滚 |
| Chromium | 校验、增改、暂停/恢复、检查、筛选、55条历史、切换/删除、断线恢复、320/390视口 |
| 验收脚本 | 陈旧身份零写入拒绝；四槽位饱和后重试并生成55条历史 |

命令见README。CI的Windows、Ubuntu作业都须通过；Ubuntu额外启用CGO执行race。实际结果以仓库Actions和Release为准，配置文件存在不等于已通过。

Playwright使用临时数据库、动态回环端口及本地上游，重试次数0，不用重试掩盖失败；失败保留trace与截图。脚本回归使用18084/18085，测试前确认无其他验收会话。

性能实验单独运行：设置PULSE_PERFORMANCE_OUT执行18组测量。查询基准为标明的合成样本，不是用户数据。

测试证明列明场景，不证明没有任何缺陷；race只检测实际运行路径。手机为视口测试，不冒充真机/触摸/移动键盘验收。尚无生产SLA或多浏览器支持承诺。
