Go helper是源码快照另行编译的程序，不能当作传入二进制内部性能的直接测量。两侧helper使用NULL旧分类数据（request_error→unknown）；HTTP schema4 fixture显式写dns，schema3无分类列。基线构建归档与Go基准快照文本在CRLF归一化后一致，原始指纹分别保留。复现见[RUNBOOK](../RUNBOOK.md)，调查helper见[investigation-helper.go.txt](investigation-helper.go.txt)，只复制到候选隔离快照中使用。

| 观测 | 结果 |
| --- | --- |
| 无查询3轮/持续查询窗口 | 15772.065 / 15782.013ms |
| 历史50条请求/写入增长 | 683次 / 400→700 |
| 请求进行期间写入增长 | 34次请求 |

查询期间每50次及轮后检查freshness，未见stale；health持续healthy，无记录的读写错误或槽位越界。两阶段时长接近，但仅一段先控制后查询的观察，不声称统计等价、尾延迟保证或生产QPS。请求前后计数证明请求活动区间内采集推进，不精确定位数据库操作同时执行时刻。这是接受约1ms新增接口成本的实际工作量证据，而非仅靠功能解释豁免。
