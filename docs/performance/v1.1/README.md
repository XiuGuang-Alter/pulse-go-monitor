## 两小时混合长跑

开始UTC：2026-11-07T13:30:16.922Z；实际运行7200.15秒，配置7200秒。100目标、并发4、完成后间隔10秒；正常50毫秒、HTTP500、1秒超时及JSON业务失败混合；每5分钟编辑并删除/替换目标。全部使用独立上游和数据库。

- 累计完成70254个样本，编辑/删除替换23轮，四类结果均出现；重启后保留100目标。
- 同目标重叠0次；Go running采样不超过4，逐目标120秒进展看门狗无停摆，未见后台存储失败；采样间断超过30秒会失败。
- Go HeapAlloc采样范围1.12–3.08MiB，末次1.92MiB；goroutine范围9–24，末次14。
- 进程RSS范围25.79–58.53MiB，末次26.17MiB；RSS每60秒读取，间隔样本沿用最近值，与Go堆含义不同。
- 上游socket峰值5仅作诊断：超时取消后Node的close回调可迟于Go槽位释放；严格实际并发上限另由固定50毫秒矩阵及调度测试断言。

结束时终止并重启专属子进程核对持久化，正常退出另由Windows私有控制台Ctrl+C和Ubuntu SIGINT测试。两小时未发现的泄漏或故障不等于不存在；不据此声称线上可用率或SLA。启动时已完成的少量样本包含在累计数中，首个瞬时速率不用于容量结论。

原始：[采样CSV](soak-samples.csv)、[运行结果](soak-result.json)、[环境](environment.json)。此前中断或源码变化而停止的预运行不计为两小时验收。

## 升级与回退

使用实际v1.0下载包创建目标与检查记录，停止后备份整个数据目录；候选迁移至版本3保留ID与旧记录NULL耗时，回填桶带不完整标记；首版拒绝升级后的数据库；原备份哈希未变，恢复副本由首版正常打开。均为临时合成数据。[结果](upgrade-result.json)。

## 复现

矩阵：设置PULSE_PERFORMANCE_OUT后执行 go test ./... -run=^TestPerformanceMatrix$ -count=1 -timeout=300s -v；测另一版本前清除环境变量并换到对应提交。

查询：go test ./... -run=^$ -bench=BenchmarkStoreQueries -benchtime=3x -count=3 -benchmem；候选另加BenchmarkDaily30Days。查询计划：go test ./... -run=TestPerformanceQueryPlans -v。Windows可用go.ps1包装相同参数。

长跑：node scripts/soak.cjs；默认7200秒，PULSE_SOAK_OUT指定项目内独立输出目录；Windows通过PULSE_PWSH指定PowerShell7。保持机器运行，休眠/执行中断不能算通过。

升级：先构建候选，再执行 node scripts/test-upgrade.cjs <首版程序路径> <候选程序路径>。普通CI不重复长跑，仍要求两系统全部检查及Ubuntu真实race；发布包独立验证见测试说明。
