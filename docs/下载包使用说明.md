# Pulse v1.2.0 · Windows使用说明

先核对包内BUILD.txt的版本和提交。v1.2使用schema4，旧程序不能直接打开升级后的库。正式包来源、hash与发布后复验见对应GitHub Release；Actions测试制品与正式发布资产分开记录。

从项目GitHub Release下载ZIP和SHA256SUMS.txt。PowerShell7执行 `Get-FileHash .\pulse-v1.2.0-windows-amd64.zip -Algorithm SHA256`，结果应与校验文件一致。解压到可写目录，不要直接在压缩包中运行。

双击“启动演示.cmd”，打开 http://127.0.0.1:8080 ，本机8091提供正常、500、超时示例。双击“启动监测.cmd”使用自己的独立数据库，首次没有目标。程序运行无需Go、Node或外置数据库。两个启动方式都默认占8080，不能同时运行。

```powershell
.\go-monitor.exe serve -addr 127.0.0.1:8082
.\go-monitor.exe serve -demo -demo-addr 127.0.0.1:8092 -db data/demo.db
.\go-monitor.exe serve -h
```

按Ctrl+C正常停止。账号与告警不在本版范围；仅供本机个人使用，请勿反向代理到公网。目标URL会存库，不要放敏感令牌或账号密码；HTTP200不证明所有业务正常。

编辑目标可设置允许状态码、正文包含和JSON值断言，例如JSON路径 `/code`、期望值 `0`。多个规则全部满足才成功；JSON期望值要用JSON标量写法，如字符串 `"ready"`、数字 `0`、布尔 `true` 或 `null`。正文最多读取解压后1MiB。已有正文或路径含换行等控制字符时，编辑器显式显示带双引号的JSON字符串及提示，保留转义即可原样保存。

历史显示响应头耗时及完整检查耗时，首版记录的完整耗时为空。UTC日汇总按当次规则累计最近30个自然日；无样本没有成功率，当天尚在进行。修改规则后，跨规则时期不能直接等价比较。

数据保存在启动目录的data文件夹，cmd脚本会先进入程序目录。先停止服务再备份整个data目录；运行中不要只复制.db而遗漏WAL日志。删除目标会删除其历史，不可通过页面恢复。

从v1.0/v1.1升级：

1. 停止旧程序并保留旧版程序包。在新版目录执行独立维护命令，-db指向旧数据库路径，输出新的完整备份并校验；读取旧库不迁移或清理。
2. 解压新版到新目录，用维护恢复命令把备份恢复到全新数据库路径；已有库或侧车会被拒绝。不要让两个程序共用数据库同时运行。
3. 启动新版并指定恢复路径，首次自动将数据库版本1/2/3升级至4，保留目标ID和历史ID。迁移失败会回滚，不应手动改数据库版本。
4. 核对目标和历史。日汇总只从仍保留的明细回填，并标注“迁移前历史不完整”，无法恢复被淘汰的明细。
5. 如需回退，停止新版，将升级前备份恢复到另一新路径，再用对应旧程序打开；旧程序拒绝schema4。不要把备份覆盖到仍在运行的程序目录。

BUILD.txt记录构建来源；LICENSE是项目许可，THIRD_PARTY_NOTICES.txt保留静态依赖与Go运行时许可。源码与运行说明：https://github.com/XiuGuang-Alter/pulse-go-monitor


## 数据维护、健康与新鲜度

v1.2提供独立备份、校验、新路径恢复、配置预检导入和历史导出命令。操作前先正常停止服务；需要历史导出ID时在停服前按维护说明查询目标列表。恢复和导入拒绝覆盖已有库。完整步骤及预算见随包的[数据维护说明](数据维护.md)，或运行 `go-monitor.exe maintain help`。完整备份与配置可能含原始敏感信息，请勿公开上传。

升级前使用新程序的维护命令备份并验证旧库，支持schema1–4；备份读取不升级旧库。首次 `serve` 才迁移。回退时停止新程序，将升级前备份恢复到新数据库路径，再用对应旧程序启动该路径；不能让v1.1直接打开schema4。

v1.2页面新增监测器自身状态与结果新鲜度。目标最后一次正常不等于当前配置已经验证，也不等于监测器仍在采集。URL指定敏感查询参数在展示中脱敏，但原始配置API、编辑界面、数据库和完整备份仍可能含秘密。分类图只统计仍保留的失败明细。上述能力不在原v1.1下载包内。
