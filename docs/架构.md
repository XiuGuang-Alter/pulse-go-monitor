# 架构与取舍

单进程本机监测工具。CLI检查单网址，serve同时提供调度、SQLite、JSON API和内嵌页面。

```text
main / serve
  ├─ server → JSON API / embedded web
  ├─ scheduler → bounded slots + per-target running set → Check
  └─ store → SQLite targets / checks / daily_summaries / monitor_metadata
```

默认Check等待最终响应头并分类。配置正文规则后，CheckWithRules继续读取解压后最多1MiB＋1字节，超限明确失败。context覆盖连接、重定向、读取和解析；状态码失败不继续读取。旧duration_ms仍到响应头，新total_duration_ms覆盖完整检查。

调度器在完成释放槽位及配置变更后以容量1的通知通道合并唤醒，每250毫秒轮询兜底。启动前再次读取配置，仍使用同一槽位及每目标running集合。存储失败至少退避1秒，避免失败立即唤醒的忙循环；不积压无界任务队列。下次时间为完成时刻加间隔，不补停机任务。

SQLite单连接简化事务；网络不占用事务。编辑递增版本，旧检查可归档快照，但只有同版本才能更新下次时间。删除有存在性检查和外键级联，历史按ID游标分页。

数据库版本1→2建立日汇总及采集起点元数据，2→3增加规则、完整耗时及检查快照列；一次启动全部待迁移步骤同事务提交。版本过新拒绝启动。升级前须停机备份；降级依赖旧备份，不做破坏性反向迁移。

检查明细插入、按检查开始时间归属UTC日期的汇总增量、明细淘汰及下次时间更新在同一事务。明细淘汰不扣减日汇总；旧数据回填带永久partial标记。日桶保留今天及前29日，无样本返回空指标。原Stats仍基于保留明细，两种统计不能混用。

列表固定三次查询：目标配置、每目标最新记录、分组统计。最新记录及历史分页使用(target_id,id DESC)索引；统计使用(target_id,checked_at,kind,duration_ms)覆盖索引。额外索引增加写入与磁盘成本，性能报告记录实测收益及分页新增字段的分配开销。

规则保存时先验证并规范化；JSON用UseNumber逐token解析，拒绝重复键、非法UTF-8和尾随JSON，最多64层容器，单个数字最长256字符、指数绝对值最多1000。十进制转换为big.Rat精确比较，避免float64舍入；Pointer遵循RFC6901，缺失与null不同。错误只保存静态原因，不存响应正文或实际字段值。PUT缺省rules保留，null重置；历史保留当次规则和版本，旧历史新增字段保持NULL。

退出取消调度和HTTP请求，等待收尾，再关闭服务、数据库；主动取消不作为目标故障。Windows真实Ctrl+C在独立隐藏控制台验证，Unix验证SIGINT。

原生HTML/CSS/JS串行刷新、以代次作废旧响应，防止写入期间回滚旧配置。手机历史表格在弹窗内部滚动，不撑宽页面。

前端使用服务端返回的原始期望值JSON字符串元数据保留超大整数；提交前只检查标量类型，发送原数字token。已有控制字符的正文和Pointer使用显式JSON字符串编辑，避免HTML单行输入或textarea换行归一化。日汇总按最新日期先显示，异步历史与汇总共同使用失效代次。

SQLite和内嵌前端让单程序即可运行；代价是单进程协调、单连接吞吐限制，改网页后也要编译。不承诺多实例协调、完整鉴权、SSRF隔离或公网能力；性能数字限于报告环境。

## v1.2 开发分支：健康与新鲜度

`GET /api/status` 保留旧的 `status` 等字段，新增 `monitor_health`。该对象区分启动中、正常、空闲和退化；目标HTTP错误本身不会导致工具退化。观察时间、最近成功扫描/落库、本进程成功落库数及实例标识用于诊断，重启后计数重新开始。数据库探测失败仍返回原有错误响应。API可访问不代表调度或结果写入正常。

调度数据库操作和状态探测设置5秒超时；最后成功扫描超过15秒显示扫描未推进。成功写入其他目标不会清除某目标的写入故障；删除后清理对应状态，暂停目标的故障不计入当前受影响目标。健康快照不访问数据库，不持锁执行SQL或网络请求。

目标列表新增 `current_config_version`、`running_since` 和 `freshness`。新鲜度与历史检查结果分开；未采样、等待、检查中、配置待验证、陈旧和暂停不改写历史Kind或统计。非在途目标以计划检查时间＋请求超时＋2秒宽限判断陈旧；在途任务使用启动时配置快照的超时，以实际启动时间＋原超时＋2秒判断。排队超出预算会标明调度延迟，并非存储故障。当前配置版本无匹配样本时，不把旧正常记录算作当前已验证。旧记录无法确定配置版本时同样待验证。

页面以服务端观察时间和浏览器单调经过时间判断数据老化，并保守计入从发起刷新到收到响应的耗时；刷新失败保留数据但标明未更新，正常数量及筛选排除陈旧、待验证、检查中和断连状态。页面健康信息是刷新时的观察结果，不能当作连续在线保证。M1未引入数据库迁移或改变明细、UTC日汇总口径。

## v1.2 开发分支：安全展示、分类与schema4

目标配置接口保留原始 `url`，兼容旧客户端；新增 `display_url` 供列表、悬浮提示、搜索和历史标题使用。创建/编辑响应使用同样约定。网页主动进入编辑时读取已有原始配置，启停使用原值，脱敏地址不会回写；API及数据库属于含原始配置的本机受信任边界，未增加鉴权或加密。

统一安全格式化隐藏查询键 token、access_token、refresh_token、api_key、apikey、secret、password、passwd、signature、sig 的值，键名解码后大小写不敏感，覆盖重复键；展示隐藏fragment。请求本身不经格式化，原参数顺序和编码保持。历史API的输入/最终URL、检查说明及CLI使用安全展示值。未知旧自由文本不尝试提取其中的秘密，而以安全概述代替；原有固定断言说明仅在完整白名单匹配时保留规则编号。日志只输出内部错误类型及目标ID，不拼原始网络或SQL错误文本。范围不包含自动识别名称、URL路径、任意规则值或任意其他字符串里的秘密。

`error_category` 是新增解释字段，保留Kind及成功判定。分类包含DNS、连接、TLS、超时、HTTP4xx/5xx/其他HTTP、正文读取、正文超限、断言、输入和未知；使用结构化错误与TLS握手阶段，不猜操作系统错误文案。成功分类为空，允许404仍成功、HTTP200断言失败仍属断言。历史缺分类只从Kind/状态码推断，旧request_error归未知。

历史API新增 `error_categories` 与 `category_scope=retained_checks`，仅统计当前保留且未过期的失败明细。页面明确其不是30日完整错误分布；UTC日汇总口径不变。

数据库schema由3升级至4，为checks增加可空分类列。1/2/3→4在同一事务完成，失败回滚，过新版本拒绝。v1.1无法打开schema4，必须使用升级前备份回退。不要将新程序直接指向唯一的真实数据副本；先停机保全备份。M3维护工具尚未完成，本阶段沿用停机备份流程。

规则错误返回固定字段名或JSON规则编号，不回显用户值；UTF-8预算按字节计算，JSON期望值只接受标量。保存失败仍保留表单输入。

## v1.2开发分支：数据维护

维护入口为同一程序的 `maintain` 子命令，源库通过独立 `mode=ro` 流程读取schema1–4，不调用会迁移和清理的OpenStore。备份使用modernc原生SQLite Backup API，以32页Step检查取消；只读事务用于配置和历史一致读取。辅助WAL/SHM协调可能变化，不将源目录逐字节不变等同于逻辑数据不变。

备份包含manifest.json与database.db。压缩/解压总预算各256MiB，manifest64KiB；在archive/zip分配目录对象之前有界校验真实目录/本地条目跨度，拒绝ZIP64、多磁盘、重复/未知路径、符号链接与超额条目。快照校验包含SHA256、schema、计数、SQLite完整性和外键。恢复保留源schema，不触发迁移或保留清理。

新输出采用同目录临时文件、Sync和原子硬链接发布，拒绝覆盖，文件系统不支持硬链接时失败关闭。恢复和导入在开始及发布前检查目标数据库与侧车；用户须先正常停止服务，该检查不等于对任意外部并发写入的隔离保证。导入在私有新库内单事务创建全部目标，关闭并合并日志后才发布；不会逐条修改原库。

配置格式版本1，默认脱敏文件不能直接导入，完整配置带敏感性标记。输入预算4MiB可容纳100目标及合法规则转义放大；逐目标规则预算不变。完整规范化配置去重，URL相同但规则不同合法，ID重新分配，默认暂停。预检不写数据库，命令行先显示数量和启用策略。

历史以checked_at和UTC左闭右开范围一致遍历，JSON保留精确规则数字及NULL。CSV固定metadata首行，其余check行；范围与保留口径每行重复，空导出也可解释。文本单元防公式注入。界面保留范围按1000条/30天先到限制解释，实际最早/最新时间与理论覆盖分开，汇总不补造已淘汰明细。详见[数据维护](数据维护.md)。
